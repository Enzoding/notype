# Notype 下一步迭代调研与方案

日期：2026-10-25。状态：待产品确认，尚未实施。范围：本地代码审阅与官方资料调研；未运行真实录音、付费请求或云端部署。文中的参数为建议值，性能和模型质量需要实测后承诺。

## 1. 建议的产品方向

保留一个开源客户端，提供两种使用方式：

| 方式 | 账户 | 密钥与模型 | 请求路径 | 收费 |
| --- | --- | --- | --- | --- |
| 自带密钥 BYOK | 无需登录 | 用户按渠道配置密钥，分别选择转写与润色模型 | 客户端直连用户指定渠道 | 用户向渠道付费 |
| 官方托管服务 | 必须登录 | 服务端管理密钥、模型和路由；客户端只展示必要偏好 | 客户端 → 官方服务 → 上游 | 后续订阅或额度包 |

同一用户可以切换方式。退出账户不影响本地历史与 BYOK；额度用尽不应删除任务，也不应偷偷使用用户另一个渠道的密钥。可靠录音、失败恢复属于两种方式共享的基本能力。

建议顺序：**可靠性基础 → 多渠道 BYOK → 账户 → 托管试用 → 商业订阅**。账户技术验证可以提前，但不要在录音仍会丢失的基础上直接出售订阅。

## 2. 现有代码结论

| 主题 | 当前行为与依据 | 影响 |
| --- | --- | --- |
| 最大录音时长 | `src/session/lifecycle.rs::begin` 在 120 秒后调用 finish | 现在是约两分钟自动停止，不支持十分钟录音 |
| 音频缓存 | `src/capture.rs` 将原始 f32 采样持续追加到内存 Vec | 崩溃无法恢复；长录音提高内存与复制成本 |
| 麦克风断流 | capture 的错误回调只输出“麦克风中断” | 没有通知业务状态、保存已录内容或恢复路径 |
| 网络方式 | 停止录音后一次上传；并非边录边传 | 录音期间断网本身不等于音频断流，上传阶段失败才影响转写 |
| 失败保存 | `deliver` 仅对 Ready 写 history，并按 save_audio 保存 WAV | 转写失败不会保存音频或失败任务；默认保存音频也不能补救 |
| 阶段恢复 | 无持久化任务、分片和阶段检查点 | 重启后不能续做，只能重新录音 |
| 重试 | 转写仅对 400/413/422 缩减热词；普通网络错误直接返回 | 缺少退避、Retry-After、可重试错误分类；413 不能靠删热词普遍解决 |
| 超时 | AI 请求共用 90 秒超时，连接测试 15 秒 | 不区分连接、上传和推理，也不按录音长度调整 |
| 润色回退 | 润色失败使用转写文本继续插入 | 已有正确基础，需要保留，并让用户稍后只重试润色 |
| 取消 | generation 校验阻止旧任务交付；blocking HTTP 未真正中止 | 不会贴入过时结果，但后台可能仍请求和产生上游费用 |
| UI 流畅度 | finish 在 UI 更新中完成样本复制、重采样、编码和 WAV 克隆；deliver 写文件和数据库 | 长录音会放大停顿，应迁到后台并返回窄结果 |
| 渠道配置 | 一个 base URL、一个 key、两个模型；转写固定 Vercel `/v4/ai/transcription-model` 协议 | 换成 OpenRouter URL 不会兼容；输入带 /v1 的地址还会重复拼接路径 |
| 模型与测试 | 设置界面已有转写/润色模型选择，但为硬编码；连接测试只调用聊天模型 | 不能代表转写可用；不是从零做模型选择，而是改成按渠道能力选择 |
| 密钥保存 | `src/secrets.rs` 写 SQLite 和 .env.local，部分写入失败被忽略 | 多密钥与登录 token 应使用 Keychain；迁移必须先验证保存成功 |

以上是静态代码结论，不代表已完成系统故障复现。

## 3. Better Auth + Cloudflare 账户体系

### 可行性与推荐架构

Better Auth 放在独立的 TypeScript 云服务中，Rust/GPUI 客户端通过 HTTPS 调用。建议 Workers + Hono + Better Auth；账户和业务元数据使用 D1，数据库访问及迁移可统一用 Drizzle。Better Auth 有 Drizzle SQLite adapter，Drizzle 明确支持 D1/Workers；这是可行组合，但所选版本、插件、迁移及 D1 事务限制必须经过部署验证，不能把普通 SQLite 的事务假设直接带进来。[Better Auth adapter](https://better-auth.com/docs/adapters/drizzle)、[Drizzle D1](https://orm.drizzle.team/docs/sqlite/connect-cloudflare-d1)。

服务端按职责拆分 auth、entitlements、usage、jobs、providers；认证表交给 Better Auth，订阅权益和 AI 用量账本由业务模块拥有。本地 SQLite 继续存历史与恢复任务，云端账户数据库不替代本地库。首期不做历史、词库和录音云同步。

### 原生桌面登录流程

推荐先使用 Better Auth Device Authorization：客户端申请设备码 → 打开系统浏览器 → 用户登录、核对设备码并明确授权 → 客户端按规定间隔轮询 → 收到会话 token → 存入 macOS Keychain。官方插件支持设备授权完成后发放本应用的 Better Auth session token；调用官方 API 可配合 Bearer 插件，不需要客户端嵌入 JavaScript SDK。[设备授权](https://better-auth.com/docs/plugins/device-authorization)、[Bearer](https://better-auth.com/docs/plugins/bearer)。

这是本项目的方案选择，并非所有桌面应用都必须用设备码。后续若追求更顺畅的一次跳转登录，再评估系统浏览器 + loopback callback + PKCE；不要把长期 token 放到自定义 URL 或网页地址里。

第一期建议 GitHub OAuth，邮箱验证码作为面向普通用户的补充（邮件服务需另外选择）。实现登录、退出、会话过期、撤销设备、删除账户；按实际 Better Auth 会话语义处理续期，不能假定设备流程自动提供 OAuth refresh token。限制设备码申请与轮询频率，网页保留来源/CSRF 校验，所有生产流量 HTTPS。网页登录 cookie 和桌面 Bearer 分开处理。

### Cloudflare 边界

Workers 处理认证、授权、调度和外部请求，不执行 ASR 推理，也不承担音频转码。当前 Workers isolate 内存上限为 128 MB；Free CPU 预算较小，网络等待不计 CPU 时间。应避免把长音频、base64、JSON 多次同时缓冲在服务端；免费额度不能作为正式服务容量承诺。[Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)。

托管服务需要持久化 job：提交后返回 job ID，客户端断线后仍能查询。短任务可同步优化，但不能只依赖与客户端绑定的长 HTTP 请求或 waitUntil 来保证完成。进入托管试用时验证 Queues/Workflows 的执行与重试语义；如需服务器持有待处理音频，再使用私有 R2、短期上传授权和自动过期清理。R2 不是第一期账户功能的必需品。

## 4. 多渠道 BYOK 与模型选择

### 渠道调研

| 渠道 | 转写 | 润色 | 首期处理 |
| --- | --- | --- | --- |
| Vercel AI Gateway | 当前代码使用专用转写协议；官方提供音频/STT 能力 | 已有 chat completions | 保留兼容性，为当前协议补契约测试，再核实支持模型和稳定接口 |
| OpenRouter | 已有专用 `/api/v1/audio/transcriptions`，支持 base64 JSON 和 OpenAI 风格 multipart | chat completions | 推荐首批接入，单独实现转写 adapter |
| 自定义 OpenAI 兼容服务 | 是否有 multipart transcription、热词和限制取决于具体服务 | 视兼容程度 | 后续提供高级配置，明确展示“未验证”能力 |

Vercel 官方已提供语音转写相关能力，但具体模型是否支持当前 Rust 使用的协议要逐一验证。[Vercel 官方说明](https://vercel.com/blog/realtime-voice-agents-on-ai-gateway)。

OpenRouter 可通过 `models?output_modalities=transcription` 发现转写模型；音频输入聊天模型不等于专用 STT。其 STT multipart 上限为 25 MB，prompt 接受但被忽略，部分聊天路由偏好不适用于 STT。官方教程还提示上游 60 秒超时，所以十分钟录音是否可一次成功不能仅从文件大小推断。[STT 文档](https://openrouter.ai/docs/guides/overview/multimodal/stt)、[官方教程](https://openrouter.ai/blog/tutorials/transcription-on-openrouter/)。

### 数据与模块设计

- `ProviderProfile`：渠道类型、显示名称、规范化 endpoint、Keychain 引用。支持多个 profile，切换渠道不覆盖另一个渠道的 key。
- `TaskModelConfig`：转写、润色、术语提取分别引用 profile + model ID。默认让术语提取跟随润色；允许转写和润色走不同渠道。
- `ModelCapabilities`：是否 STT、格式、大小/时长上限、热词、时间戳、流式能力和已验证状态。缺少能力时明确提示，不静默丢参数。
- `providers/`：transport、错误分类、vercel、openrouter、模型目录；流水线只接收统一输入和结果，不理解渠道协议。
- 模型目录使用渠道 API + 本地缓存 + 人工验证推荐列表。允许高级用户填 model ID，但连接/能力验证通过后才标为可用；失败时保留上次可用目录。

设置界面先选“官方托管 / 自带密钥”，BYOK 下选渠道、密钥和模型。测试分别覆盖密钥/聊天连通和小段合成音频转写，并说明测试可能产生渠道费用。不能继续把聊天成功展示为整个转写链路成功。

旧配置迁移为默认 Vercel profile，保留原有模型与 URL；密钥先写 Keychain、读回验证成功后才清理旧明文副本。失败则保留旧值并显示迁移状态。备份不能把密钥引入普通诊断日志。

## 5. 十分钟录音、断流和恢复

### 持久化优先

第一步仍保持“录完再转写”，先实现稳定恢复；边录边转写作为后续降低延迟的独立优化。

录音开始即创建 UUID 任务，采集回调只做轻量处理和投递，通过有界队列交给后台写盘线程。队列溢出必须上报，不能无声丢帧。采样转换、重采样、文件编码、SQLite 写入都放后台；UI 只读状态快照。

建议每 2–5 秒形成可恢复检查点，使用分段音频文件、原子完成标记与 manifest，启动时协调文件和 SQLite：可恢复完整片段，截断/隔离未完成尾段。保证边界是“保留最后一次成功持久化的音频”，不能承诺进程被杀或掉电时零丢失。磁盘满或写入失败时停止并保留已写部分，提示用户处理，不继续制造无法保存的录音。

任务数据至少包含：task ID、attempt/generation、阶段、音频片段与时长、采样格式、渠道/模型快照（不含 key）、原始转写、校正结果、润色结果、结构化错误、重试次数与下次时间、创建/更新时间、交付状态。任务仓库独立于最终 history 仓库，成功后关联历史记录。

### 状态与失败处理

建议状态：`Recording → Captured → Transcribing → Transcribed → Polishing → Ready → Delivered`；另有 `Interrupted / RetryWaiting / Failed / Cancelled`，保留失败发生阶段。

| 场景 | 预期行为 |
| --- | --- |
| 录音中断网 | 本地继续录，停止后展示等待网络/手动重试 |
| 麦克风拔出、设备报错、系统休眠 | 业务收到事件，结束当前段并标记中断；保留已有音频，提示选择设备后继续新段或处理现有内容 |
| 应用崩溃/强退 | 重启列出未完成任务，用户确认后恢复转写；不自动向当前应用粘贴旧内容 |
| 转写失败 | 音频保留，可重试失败阶段；401/403 提示修复配置，429 尊重 Retry-After，网络/部分 5xx 有界退避 |
| 请求超时但上游可能成功 | 标记结果不确定；托管模式先查 job，避免直接创建新任务；BYOK 提醒重复请求可能产生上游费用 |
| 润色失败 | 保留原文，延续当前回退行为；之后只重试润色，不重新转写 |
| 粘贴失败 | 文本已持久化，可复制/重新插入；不重新调用 AI |
| 用户取消 | 持久化取消标记并使旧 attempt 失效，尽可能中止传输；迟到结果不能改变新任务或触发粘贴 |

自动重试建议最多 2 次，指数退避加抖动；永久配置错误、损坏输入不自动重试。413 应根据能力调整分片或编码，不重复上传同一大文件。取消录音和删除录音分成不同操作，明确取消后是否保留恢复草稿。

### 十分钟支持策略

当前输出是 16 kHz / 单声道 / 16-bit PCM WAV，十分钟约 19.2 MB，base64 后约 25.6 MB（不含 JSON 开销）。这是按当前编码计算，不代表上游都能处理。若一直缓存 48 kHz 双声道 f32，十分钟原始采样就约 230.4 MB，尚未算结束时的复制、WAV 和 JSON。

建议先把十分钟作为显式上限，接近上限提醒，到点自动结束并保存。先完成磁盘录音和恢复，再提高 120 秒限制。

转写按渠道时长/字节限制及实测延迟分片，初始可试 30–60 秒，在静音附近切分，必要时少量重叠。持久化每片结果；合并使用时间戳或保守边界匹配，避免简单字符串去重误删正常重复词。只有失败片重试；全部完成后再统一润色，长文本按上下文窗口处理，保留未润色完整原文。

磁盘检查点与 ASR 分片是两种尺度：前者保护录音，后者适配模型请求。首期不依赖供应商提供真正的断点续传；失败可重发一个已保存分片。

### 保存与隐私建议

将“处理期间安全缓存”与“成功后长期保留录音”拆成两个设置。建议失败/未完成任务保存 7 天并可手动保留；成功后按现有 save_audio 偏好保留或清理。到期清理要有可见规则，重试中的任务不能被清理。可选不落盘隐私模式，但明确关闭崩溃恢复。托管模式另行展示上传对象、服务端保留时长与删除入口，本地删除和云端删除的作用范围要清楚。

## 6. 托管与订阅前置设计

登录解决身份，盈利还需要服务端强制权益与计量。开源客户端里的付费按钮和本地判断不能成为访问控制依据。

- 官方供应商 key 仅在 Workers secrets；服务端限定模型、任务大小、并发和超时，不能提供任意 URL 转发。
- 权益表区分套餐、有效期、额度周期；账本区分预留、结算、释放、调整，不直接反复修改一个余额字段。
- 每个 task/stage/chunk 使用幂等键；客户端重试返回同一业务任务，服务端重投不能重复扣用户额度。上游是否重复收费另行记录与对账，不能对所有供应商承诺 exactly-once。
- 额度预留必须是原子条件操作，成功后按实际音频时长/套餐规则结算；失败释放或进入不确定待对账。不能用 KV 最终一致读写控制余额。
- 防止伪报时长：按接收到的音频信息校验，使用上游 usage 交叉对账；限制音频格式和大小。并发请求、双击、Webhook 重放均不得超扣。
- 建议售卖“每月包含若干录音分钟”，内部另记润色 token、失败重试、基础设施与支付成本。暂不提供无限量承诺。
- 价格依据匿名/合成样本测得的模型成本与成功率制定：单用户成本 = 转写分钟成本 + 润色 token + 重试放大 + 云端/邮件/支付 + 支持成本。不在没有调用数据时拍定套餐价格。
- 首期账户可先发测试权益；真正订阅再选择支付渠道，补齐签名 Webhook、幂等事件、续费失败、退款/撤销权益和对账。Better Auth 不代替这些业务规则。

## 7. 分阶段交付与验收

| 阶段 | 交付内容 | 完成标准 |
| --- | --- | --- |
| P0 可靠性 | 录音写盘、任务仓库、失败恢复、阶段重试、后台编码与持久化；再开放十分钟 | 十分钟录音可保存；转写前强退可恢复到最后检查点；断网/磁盘满/拔麦有明确状态；取消无迟到粘贴 |
| P1 多渠道 BYOK | providers 模块、profiles、Keychain 迁移、OpenRouter、模型能力目录、分阶段连接测试 | 原 Vercel 配置可用；两渠道独立 key；转写/润色可分别选渠道；错误模型与不支持参数可解释 |
| P2 账户 | Workers 服务、Better Auth、D1 迁移、网页授权、Keychain token、设备退出/撤销 | 真机浏览器登录闭环；过期/取消/重复授权正确；退出不破坏 BYOK；测试和生产隔离 |
| P3 托管内测 | 持久化 jobs、服务端路由、测试权益、原子额度预留/结算、幂等与指标 | 请求后客户端断线可查回结果；重复提交不重复扣用户额度；服务端无文本/音频/密钥日志泄漏 |
| P4 商业发布 | 支付、订阅状态、套餐、删除与保留政策、用量页、成本控制 | 完成订阅到使用、额度耗尽、取消续费、退款与Webhook重放的完整验证 |

每阶段独立 review，避免将大规模账户改造与录音状态机一次合并。建议新增本地 `recording/`（采集和恢复文件）、`tasks/`（纯状态机及仓库）、`providers/`、`account/`，逐步把 Session 缩回协调层。提取时传明确输入输出，不把整个 Session 传进新模块。同步更新 AGENTS.md 中模块边界和开发命令。

验证包括：纯状态转换、空音频、畸形响应、失败请求、旧 SQLite 迁移、文件/DB 不一致恢复、取消与迟到结果、重试幂等。实现后运行 fmt、相关单测与 Clippy；在 macOS 真机完成 record → transcribe → polish → paste，包括取消和润色失败回退。用合成音频在两渠道验证 10 秒、2 分钟、10 分钟，记录峰值内存、UI 停顿、停止到出字时间和恢复成功率；目标数值由基线测试后确定。

## 8. 待确认的产品决定

1. 是否采用“BYOK 无需登录且免费；官方托管需要登录并付费”的边界？建议采用。
